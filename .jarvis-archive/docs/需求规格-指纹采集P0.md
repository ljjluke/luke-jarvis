# 需求规格 - 指纹采集 P0

## 需求本质

- **为谁**：安全运营人员与客户验收方。他们看已扫资产详情时，目前只有「端口 / 服务名」这类原始文本，无法回答「这台机器跑的什么 Web 服务器、什么版本、有没有已知组件」。
- **解决什么**：把已有的扫描文本结果（ports / server / xPowerdBy / detail）**被动解析**成结构化分层指纹，穿透到「产品 + 版本 + 置信度 + 证据原文」，在资产详情页可见、可下钻看证据。
- **怎样算成功（可判定）**：见第 2 节每条验收标准 + 第 5 节 V1–V7 机械判据。核心三条：① 族≠版本硬约束成立（V1=0）；② 无证据不入库（V2=0）；③ 详情页能看到服务/版本/Web服务器/PHP版本且证据可展开（V5）。

## 功能清单

|---|---|---|---|

| F9 | 新版 SPA 适配 | 新版由 iframe 承载 `/device/detail.html?id=`；保证指纹分层展示在新旧两套 UI 都看得到 | 在新版前端打开资产详情，指纹区块可见、证据可展开、"分层"可下钻 |
| F10 | 策略模板 fp_profile | 表 + safe/standard/deep 三档种子，与 tmp_sysconf/tmp_gkconf 并存互不影响 | select count(*) from fp_profile = 3 |
| F11 | 出厂规则 5 条 | Spring Boot / PHP / ThinkPHP / nginx / Django，全 enabled=0；Spring Boot implies Java+Tomcat | V4：select count(*) from fp_rule where enabled=1 = 0 |

## 边界

- **不做**框架 / Java 版本主动探测（归 P1）
- **不做**规则库 100 条灌入（归 P1）
- **不碰**漏洞扫描链路、**不改**任何现有表结构、**不做** DROP
- **不改**任何现有业务行为（唯一例外：fp.enabled 开关）
- **存量回填只允许覆盖 `r_dev_result.ports` 非空的资产**；对外文档严禁出现「全量回填 / 全部资产补齐 / 存量全覆盖」
- **不做**认证后数据库版本、TLS 证书链能力（归 P1/P2）

## 约束

- **技术**：工作空间 `/opt/work/scan/rhscan-local`（Eclipse 工程，无 pom.xml / 无 build.xml，用 javac 编译到 rhscan.jar）；JDK 版本与既有构建方式一致；依赖 jar 取自现盘 `WEB-INF/lib/`
- **性能**：P0 零新增网络请求（req_count 恒 0）；A 通道纯本地解析，不得引入明显耗时
- **稳定性**：所有新模块入口 try/catch，异常只记日志不冒泡，绝不影响 RpcImpl 主流程入库
- **兼容**：新旧两套 UI（JSP + SPA）都要能看到指纹；现有表一列不改
- **合规**：不编造版本号、不把 CDN/WAF 特征当源站框架、无证据不入库
- **时间**：P0 约 8–9 人日
- **回滚**：`update sys_config set conf='0' where name='fp.enabled'` 一行熔断，表保留

## 参照基准

本需求是「在现有资产详情页**新增**指纹分层能力」，不是替代/重建已有系统。
- **对照源 = 现有 `WebContent/device/detail.jsp` 的端口表结构 + `DeviceController.java` 现有返回结构**：新增区块插在端口表下方，不改既有字段与交互
- **对齐边界**：功能/结构对齐现有详情页风格；**不新造设计语言、不改现有端口表**
- **新版 SPA 侧**：由 iframe 承载 `/device/detail.html?id=`，改动落在旧 JSP 即两套 UI 同时生效；SPA 侧若需独立展示，需与 JSP 保持一致
