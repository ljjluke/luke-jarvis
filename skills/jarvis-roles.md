# Jarvis 数字员工 · 角色卡的项目沉淀与复用指南（领域无关，非静态卡库）

> ⚠️ **插件无卡原则（不可违反）：本插件（luke-jarvis）不携带任何静态角色卡、任何人名方向、任何领域模板。**
> 角色卡只能来自两个合法来源，绝无第三个：
> 1. **本项目沉淀**：`<项目>/.jarvis/cards/` —— 本项目自己蒸馏过、角色在本项目干出过成果的卡（经验属于项目）。
> 2. **现场 web 蒸馏**：按本次需求搜索该领域真实可查证权威 → 现场写六段式卡 → `jarvis_distill` 校验。
> 任何"插件里的卡 / 其他项目的卡 / 网上复制来的卡" = 非法来源，一票否决。

## 一、项目沉淀目录（每个项目自己的资产仓库）

```
<workspace>/.jarvis/
├── cards/              # 本项目蒸馏过的角色卡（每张 .md：六段式+source+防冒名+协同段）
├── process-*.json      # CEO 定稿的领域流程（阶段/闸门/红线/必须角色/会议触点）
├── components.json     # 能力补足引入/自研的组件清单（名字/功能/用法/维护者）
├── board.json          # 统一黑板（会议驱动协作的状态）
└── lessons.md          # 项目经验教训（复盘沉淀，防重复踩坑）
```

用 `jarvis_store`（scaffold/save/reuse）管理这套目录：它只给结构与规则，文件由 CEO/成员在工作区落盘。

## 二、蒸馏一张新卡（每次建队必做的动作）

对团队里的**每一个角色**（CEO 与每个下属）：

1. **按本次需求锁定职责范围**（如"支付风控"而不是笼统"安全"）——职责范围越贴合任务，蒸馏越准。
2. **web 搜索该职责领域的真实权威**（`web_search`，必要时 curl 官方来源）。**真实存在、公开可查证**是前提；搜不到可查证的真人 = 不许造卡。
3. **现场写六段式角色卡** + （CEO 卡）协同架构段 + **真实 source 出处** + **防冒名声明** + **（非 CEO 卡）我的协同段**：
   ```
   身份定位：<本次团队里的位置，一句话>
   思维模型：<他做这类决策时第一反应想到的那套框架>
   核心方法论：<1–2 条可执行原则/步骤>
   代表作品：<本次 web 验证的真实出处，注明"参考其框架"而非署名>
   决策红线：<什么情况一票否决/宁可不做>
   语言风格：<产出交付物时的口吻与结构习惯>
   [我的协同：<我的位置/依赖谁/给谁喂产出/向谁升级> —— 非 CEO 卡必备]
   [协同架构：<位置/依赖/介入时机/协同方式> —— CEO 卡必备]
   [source：<本次搜索到的真实出处 URL/文献>]
   [防冒名声明：只借鉴框架，不冒充署名]
   ```
4. **`jarvis_distill` 校验**通过后，才作为 `agent_teams_add_member` 的 `role` 注入；同时落到 `.jarvis/cards/<角色>.md`（`jarvis_store` save）。校验失败（无出处/卡不真实/结构不全）→ 重新蒸馏，不降级直用。

## 三、复用规则（关键：复用"项目自己的经验"，不是复用"卡"）

- **本项目沉淀可复用**：后续需求/项目变动时，`.jarvis/cards/` 里本项目角色干过的卡是经验起点——但复用 ≠ 照抄：
  ① 过 `jarvis_distill` 结构校验；② 按新需求修订（职责范围/领域/约束变了，就重新蒸馏对应部分）；③ 修订后作为新版本写回沉淀（不覆盖历史，保留演进线）。
- **跨项目禁止复用**：项目 A 的卡给项目 B 用 = 把别人的经验当自己的，且未按 B 的需求蒸馏——禁止。要用 = 重新现场 web 蒸馏。
- **插件/本指南无卡**：本 SKILL 中的所有示例字段只是"卡的结构说明"，不是可注入的卡。
- 真实情况优先于角色卡：员工按框架思考，但结论必须来自真实代码/数据/复现；不得为迎合角色卡而歪曲判断。
- 不冒充署名：任何交付物只注明"借鉴其方法"，不写"某大师说"。无出处不蒸馏；虚构人物 = 一票否决。

## 四、校验器（防"套旧卡/编造卡"双缺陷）

- `jarvis_distill`（证据链硬闸）：六段式、source 真实 https URL、防冒名独立声明、证据链/诚实边界/保真度、非 CEO 卡"我的协同"段、CEO 卡协同架构——任缺不通过。
- `jarvis_fidelity`（保真度审计）：一手占比 / 三重验证 / 诚实边界 / 矛盾保留 / 黑名单源回避。
- 校验不过 = 打回重蒸；宁可 60 分诚实，不要 90 分编造。
