# Jarvis 数字员工 · 角色卡蒸馏指南（方向库，非静态人员卡）

> ⚠️ **最高铁律（不可违反）：每次建队，每一个角色卡（含 CEO 卡）都必须现场新蒸馏。**
> `.jarvis-roles/*.json` / `domains/*.json` / 本 SKILL 中出现的任何人名/卡样，**只作「往哪个方向找真人 + 该职责该覆盖什么」的参考**。
> **绝不把任何一张已写好的卡（含下面的示例卡）直接复制/注入**为本次成员的角色——即使同领域同职责，也要按本次需求重新 web 搜索真实权威 → 现场写卡 → `jarvis_distill` 校验。
> 这一条与 CEO 协议(ceo-protocol.md v2)的最高铁律一致。违反=「套旧卡」，是系统明令禁止的缺陷。

## 一、每次建队的强制流程（先做这个，再看方向库）

对团队里的**每一个角色**（CEO 与每个下属）：

1. **按本次需求锁定职责范围**（如"支付风控"而不是笼统"安全"）——职责范围越贴合任务，蒸馏越准。
2. **web 搜索该职责领域的真实权威**：搜"该领域 关键人物/方法论/代表作"（可用 web_search，必要时 curl 官方来源）。**真实存在、公开可查证**是前提；搜不到可查证的真人 = 不许凭空造卡。
3. **现场写六段式角色卡** + 协同架构段（若 CEO 卡）+ **真实 source 出处** + **防冒名声明**：
   ```
   身份定位：<本次团队里的位置，一句话>
   思维模型：<他做这类决策时第一反应想到的那套框架>
   核心方法论：<1–2 条可执行原则/步骤>
   代表作品：<本次 web 验证的真实出处，注明"参考其框架"而非署名>
   决策红线：<什么情况一票否决/宁可不做>
   语言风格：<产出交付物时的口吻与结构习惯>
   [协同架构：<位置/依赖/介入时机/协同方式> —— CEO 卡必备]
   [source：<本次搜索到的真实出处 URL/文献>]
   [防冒名声明：只借鉴框架，不冒充署名]
   ```
4. **`jarvis_distill` 校验**通过后，才作为 `agent_teams_add_member` 的 `role` 注入。校验失败（无出处/卡不真实/结构不全）→ 重新蒸馏，不降级直用。

## 二、六段式模板（卡的结构，不是卡的內容）

```
身份定位：<在团队里的位置，一句话>
思维模型：<他做这类决策时第一反应想到的那套框架>
核心方法论：<1–2 条可执行的原则/步骤，员工能照着做>
代表作品：<1–2 个真实出处，注明"参考其框架"而非署名>
决策红线：<什么情况下他一票否决 / 宁可不做>
语言风格：<它产出交付物时的口吻与结构习惯>
```

> `role` 会进入该成员的 system prompt。整段粘贴即可，保持精炼、可执行。

## 三、职责 → 方向速查（只告诉你往哪找真人，不是给你的卡）

| 职责 | 可考虑的真实权威方向（示例） | 领域锚点 |
|---|---|---|
| 产品 | 持续发现/PMF 方向（如 Sean Ellis、Marty Cagan） | 先定义用户价值与成功指标再谈功能 |
| 架构 | 演进式架构/重构方向（如 Martin Fowler） | 可逆决策快、不可逆慢、警惕过度设计 |
| 研发 | TDD/XP 方向（如 Kent Beck） | 测试先行、小步重构、可读可测 |
| 测试 | 探索式测试方向（如 James Bach） | 风险驱动、报告可复现、金字塔 |
| 安全/风控 | 威胁建模/资金风控方向（如 Bruce Schneier） | 假设攻击者聪明、默认拒绝、资金底线 |
| 供应链/履约 | 精益生产/JIT 方向（如丰田生产方式） | 拉动式、消除浪费、安全库存 |
| SRE | 大规模运维/SLO 方向（如 John Allspaw） | 可观测、回滚、无责复盘 |
| 文档 | 以读者为中心方向（如 Ann Handley） | 先结论后细节 |

> 表里是**方向示例**：现场蒸馏时 web 搜索确认该领域**最新/最贴合本任务**的真实权威（可能不在表内），按本次业务上下文写卡。表内人名**绝不直接作为卡的內容注入**。

## 四、校验规则（`jarvis_distill` / 自查）

- `source` 必须是**本次 web 验证的真实出处**；无出处 = 不通过，重新蒸馏。
- 卡必须是**现场基于本任务写的**，不得与已沉淀的旧卡逐字相同。
- 六段式结构完整；CEO 卡必须含协同架构段（位置/依赖/介入时机/协同方式）。
- 含防冒名声明："只借鉴框架，不冒充署名"。产出不得以"某大师说"包装。

## 五、铁律清单（违反任一即缺陷）

1. **每次建队，每个角色卡必须现场 web 蒸馏 + 校验**；本库/域库/示例卡绝不直接复用。
2. 真实情况优先于角色卡：员工按框架思考，但结论必须来自真实代码/数据/复现，不得为迎合角色卡而歪曲判断。
3. 不冒充署名：任何交付物只注明"借鉴其方法"。
4. 无出处不蒸馏；虚构人物/编造方法论 = 一票否决。
