0阶段零 · 项目记忆库 & 判领域入口
用户敲 /jarvis 提需求可能详细、可能模糊（"做个东西"/"你好"）
→

→
判领域方向能判自判；判不出 → ask_user_question 引导用户说详细（"想做什么/解决什么问题/给谁用"）→ 从描述判领域
→
蒸馏猎头并注入（人才调度层先就位）猎头=人才唯一入口：供 CEO/专家/员工/补位；过 distill 双闸
→
猎头供 CEO → 贾维斯确认 → 蒸馏注入CEO=该领域公司内部老大（真实大佬，六段式卡过校验）
→
CEO 定领域专家搭档需求最需要的子领域专业视角，猎头调度给 CEO 确认
🔗 续接四件套（新会话识别 .jarvis/ 直接继续——project.md 必须持续维护）

② 下一步下一个动作（做什么+谁负责+触发条件）→ 新会话从这接着干

1阶段一 · 需求打磨（理解透彻才开工）最关键
① 独立思考·真疑问才问CEO+专家按角色卡深度思考 → 审视用户信息本身（矛盾/不可行/前提错/更优解）→ 真疑问才 ask_user_question 问尽（不设数量上限）；思考后无疑问（需求详细自洽）直接进，不硬凑问题
→
② 蒸馏团队 → 全员各自 ponder每个角色先把需求思考透、有自己的见解（理解需求后才提建议）
→
③ 全体开会畅所欲言（头脑风暴）按角色工作方式风格；每提议走"提议→任何人可解答/同意/反驳→全员表态"三轮，辩到多数认同或 CEO 裁决；挑战用户信息
→
④ 归拢·产出最好的结果共识+分歧+待用户确认 → 写公屏；坏方案被反驳淘汰、好方案吸收胜出（不是并集/折中/多数即对）
→
澄清完成判定需求本质（为谁/解决什么/怎样算成功）+边界+优先级+约束+用户对账确认
→
《需求规格》产物闸功能清单每条带可判定验收标准 + 参照基准（替代类必立）+ 用户确认项 vs CEO 推断项
⚠️ 没规格不进拆解
2-3阶段二·拆解 + 阶段三·领域流程拆解
CEO/架构师拆解需求拆成功能块/任务（不许随便拆）
→
jarvis_taskgraph 结构闸依赖闭环/无循环/每任务可判定验收/输入来源明确/编制健康（不许 CEO 一人包办）
→
CEO 定领域流程jarvis_process：必经阶段/验收闸门/红线/必须角色/会议触点（按本单需求特性，不照搬）
→
可行性闸需求超领域技术边界 → 反馈"不可行+依据+替代方向"，不可行项不进任务 DAG
4阶段四 · 建队与派活组建
🕵️ 猎头在场硬闸需要新蒸馏人物 → 猎头必须先在场（人才唯一入口）；复用沉淀卡须声明"复用卡:xxx(已过校验)"；注入前自检四问
→
CEO 写《员工需求单》角色/职责范围/能力经历/思维品格/红线/输出物（详细到能对标真人）
→
猎头逐岗寻访真实权威三重验证（真实存在/方法论独有/对照需求单逐条适配）→ 候选人对标"满足/不满足+证据"
→
CEO 逐个确认够格不满足 → 猎头重找；卡过 distill 双闸 + fidelity 保真度
→
agent_teams 建队name=该领域真实职位名；协同架构设计（jarvis_collab 四要素）
→
🧠 模型池按岗位分配CEO 按每个岗位的能力需求，从模型池选配不同优势模型（agent_teams_add_member 支持 provider/model/effort）：分析岗→推理强模型，实现岗→执行/代码强模型，测试岗→批判强模型（或与实现不同模型=真异质防同频）；注入注明理由（该岗靠什么能力）；池里缺→上报资源需求；后续迭代：池管理/能力档案/自动选模
→
编制硬闸（5.5）当前阶段人配齐，活不许压 CEO 一人；taskgraph 编制健康检查
→
CEO 设计任务+派活任务名/负责人/依赖/验收标准；派活必带 jarvis_member_brief 开工须知
→
《方案设计》产物闸总体方案/接口契约/逐条需求→实现落点/风险对策/验证方式；没方案不许写实现
📈 分阶段建队（5.6）——客户先只要方案、验收后继续走
按当前阶段配人客户只要方案 → 只配方案角色，不提前配满开发/测试（避免空挂）
→
阶段推进自动触发扩充客户确认继续/本阶段验收通过/下阶段无人承接 → 贾维斯提醒 CEO 提需求单 → 猎头补人注入
→
收口时先问"是否继续"继续 → 触发扩充；不继续 → project.md 记"下一阶段要补的岗位"，下次直接补人
5阶段五 · 会议驱动协作循环（核心执行期）执行循环

→
头脑风暴三步（贯穿全程）①各自 ponder → ②全体开会畅所欲言（提议三轮回应）→ ③归拢最好结果；没 ponder 就开会=现想附和
→
各自独思/干活关键决策跑 ponder 满血十阶段（有 run_id 才算真跑）；产出写公屏
→
测试角色先出《测试验收单》需求规格每条功能映射测试项+整体验收项；测试从需求出发，不从开发方案抄
→
开发-测试迭代循环实现（对照参照基准，禁止自己发挥）→ 独立验证 → 缺陷反馈 → 修复重打包 → 回归 → 直到测试通过
→
黑板即真相 + 按需二次会问题/决策/风险/阻塞集中 jarvis_board；阻塞未决或未决项≥3 → cycle 会；分歧 ponder 后 jarvis_review 裁决
→
红线条条问题上行三件套/资源需求上公屏/卡住限时上报（20-30分钟）/执行CEO最高优先级指令/待命成员要被唤醒/慢要查根因
★ponder 满血十阶段（每个角色深度思考的完整管线）独立于主流程，贯穿全程
🧠 十阶段固定顺序（interview → shensi → divergence → bagua → plans → converge → score → simulate → debate → synthesis）· 每阶段 step-guard before/after 记录 · 产出经 orchestrate 落盘 · run_id 溯源 · 可被 jarvis_ponder_check 核验
① 采访 interview五诊画像（天/地/人/法/物）先查共享信息，真缺才问用户；无知自检（2-5个"我知道我不知道"）
→
② 神思 shensi前提审视+跳出常规；产 stake 赌注判定；问题消解（质疑问题该不该这么问）；损失态度自检
→
③ 发散 divergence吃神思产出；6 视角审视；高赌注做视角互否（对立视角互质疑再合题）；共识=互否后存活
→
④ 八卦镜 bagua吃发散共识；8 维度并行 agent（F1驱动力~F8平衡）；⛔产出必须覆盖全部8维（orchestrate 硬校验，缺维 BLOCKED）
→
⑤ 方案 plans高赌注先做终态画像（反向链拆到今天第一步）；每方案一个 agent 并行；高赌注做正题→反题→合题辩证
→
⑥ 收敛 converge吃 plans；淘汰弱方案保留幸存；高赌注输出工作立场（倾向哪个+凭什么+什么会改主意）
→
⑦ 方案评分 score每个幸存方案一个 agent 并行，8 维度评分；高赌注对最高分归因；评分合法性可疑触发先验自检
→
⑧ 推演 simulate⛔无论赌注必做；每个幸存方案一个隔离 Subagent 推演场景；必须全部返回展示
→
⑨ 辩论 debate⛔无论赌注必做；每方案立论 agent 并行 → 攻击评估 → 抗压排名表；高赌注输出立场演化；系统反事实排查
→
⑩ 综合 synthesis最终结论+风险+结论自反+可谬标注+不可同化项+立场谱系+偏好自省（synthesis_guard 兜底互斥）
→
用户确认核心方向综合后仍需用户拍板的（非信息确认）→ AskUserQuestion 带选项 → 出最终结论
🔒 ponder 真实性核验（防"声称跑完实际乱序/缺阶段"——jarvis_ponder_check 四查）
① 完整性十阶段是否全记录（缺哪些）
② 顺序sequence 是否按固定顺序（无记录=无法核验）
③ 子 agent 数bagua≥8/plans≥5/score≥3/simulate≥3/debate≥3
④ 产出证据阶段文件是否真落盘；run_id 与声称一致；superseded_run 非空=被覆盖
PASS 才算真跑完FAIL/无法核验 → 打回重跑；成员回合中断→下回合续跑同一 run

治理分级 L1-L5先纠偏 → 纠偏无效才升级 → 连续2次不达标/需求对齐度=0 → 猎头补位（先交接文档再换人）
→
员工主动猎头补强卡覆盖不了的专业缺口 → 申请现场蒸馏该方向真实大佬作横向支援

三产物闭环核对需求规格 ↔ 方案设计 ↔ 测试验收单 逐条闭环（jarvis_coverage 自动核查：未覆盖/悬空/未收口/无证据 → 打回）
→
🛡️ 防迎合收口总闸（9条逐项核对）①审视过用户信息 ②挖过客户真实意图 ③全员异质审校 ④对抗碰撞 ⑤真实验证 ⑥没脑补补齐 ⑦测试独立于开发 ⑧回归需求本质 ⑨无迎合痕迹（essence 四查 PASS）——每条要证据，收口报告附核对表
→
用户视角走查闸以用户身份完整走一遍：主流程连起来+每处细节+弹窗子页+视觉+持续使用段（动态稳定性）；走查有证据
→
jarvis_release 打版本需求本质逐条 → 交付物 → 自测结果 → 甲方逐条确认（验收单）；可回滚

❌ 否决 → 回滚/重做闭环
⏱ 超时 → 默认通过或明确挂起
→

8项目复盘 · 沉淀资产
复盘三问做成了什么 / 哪卡壳了（需求不清/排期/角色不匹配）/ 下次怎么更好——对事不对人
→
沉淀项目记忆库角色卡→cards/、流程→process-*.json、教训→lessons.md、项目细节→project.md（含续接四件套，不许留"待补充"空项）
→
下次新需求回到阶段零 → 读记忆库 → 读续接四件套 → 直接续接/复用+修订
贯穿全流程的红线（违反即缺陷）：① 真实优先，不编造（source/数据/成果一票否决）② 需求本质回归（jarvis_essence 四查：回归本质/防迎合/防幻觉/真实优先）③ 独立思考审视用户信息，"觉得没啥问题≠真没问题"（说没问题前自问查过/验过/碰撞过吗，主动找反例）④ 头脑风暴产出最好的结果（提议→人人可答可反驳→表态收敛）⑤ 没想透不许做，没验证不许说完成 ⑥ 问题早暴露（卡住限时上报/问题上行三件套）⑦ 用户中途/收口后再提需求=新需求，同样先打磨再拆解分员工 ⑧ 需要新蒸馏人物→猎头必须在场 ⑨ 同底模不同频：哲学（可错论/视角主义/辩证对抗）+ 角色卡差异化思维 + 按职责查证异质（查证通道矩阵，禁脑补补齐）。
查证通道矩阵：查资料先真调默认搜索工具（web_search）→ 不可用自动降级 ①web_fetch 抓已知 URL ②公开检索端点（平台搜索 API 等）③直接网络抓取 → 查到标来源、查不到如实标注"查证受限/推演"，绝不脑补。
