# jarvis 能力规划（底座 = DeepSeek Harness，jarvis = 插件）

> 定位一句话：**DSH 提供"能干活"的底座（agent 循环、工具、会话、Web、存储、子代理、团队）；
> jarvis 只做"像一家公司在干活"的那一层**——流程、组织、记忆、验收。UI 是这一层的显示器，不是这一层本身。

---

## 一、边界：什么是底座的，什么是 jarvis 的

| 层 | 归属 | 内容 | jarvis 的用法 |
|---|---|---|---|
| L0 运行时 | **DSH** | agent 循环、会话/压缩、工具执行与 guard、systemPrompt 分段、子代理、`webServer`、fs/storage、commands | 只用，不重写；升级 DSH 不应让 jarvis 改代码 |
| L0.5 团队 | **DSH 插件 `@nanmicoder/dsh-agent-teams`** | 团队、成员、任务、claim/attempt、mailbox | 封装成 `jarvis_dispatch_task`（拼卡+须知+建任务+唤醒） |
| L1 流程引擎 | **jarvis** | 六阶段状态机（clarify→decompose→design→build→execute→close）、三段 guard、flowguard 闸、会议判定 | 全部**从磁盘事实算**，每请求重注入、每次工具调用重判 |
| L2 组织与协作 | **jarvis** | 蒸馏角色卡、派活、会议（纪要=证据）、绩效换人、问题上行、分歧裁决、能力补足 | 31 个工具中的 org/review 域 |
| L3 知识与资产 | **jarvis** | `.jarvis/` 记忆库（project/board/cards/process/lessons/docs）、基线清单、覆盖矩阵、指纹 | 项目内嵌、随项目走 |
| L4 交付与验收 | **jarvis** | 需求规格→方案→验收单三产物闭环、release 版本、coverage 覆盖率、ponder 核验（可选） | 收口闸强制 |
| L5 UI 契约 | **jarvis 定义，UI 实现** | 快照 `/api/jarvis/state`、摘要 `/api/jarvis/summary`、能力清单 `/api/jarvis/capabilities`、命令（工具）+ 事件（P1） | UI 只依赖契约，不读 `.jarvis` 文件布局 |

**铁律**：jarvis 不碰 DSH 内部实现，不改 agent 循环；所有"强制"用 guard/工具/磁盘判定，不用提示词。

**UI 契约设计原则**（写进 `docs/执行流程.md` 与本文档同步维护）：
1. UI 只读快照 + 只发命令，**不直接改 `.jarvis/` 文件**（否则绕过闸，等于破坏流程）；
2. 快照只读、无副作用、字段可缺省（UI 按存在与否渲染）；
3. 所有命令走既有工具语义（= 和 CEO 在对话里做同一件事），权限与校验不另开一套；
4. 快照带 `schema` 版本，破坏性变更必须升版本号并提供兼容层。

## 三、路线图（每期可独立验收，不阻塞下一期）

### P0（已完成，作为基线）
六阶段机 + 三闸 + 记忆闸 + 一步派活 + 卡注入 + 三产物闭环 + 快照 v1 + 抗压缩（阶段段创建即挂、续接事实）。

### P1（接下来，直接服务"增强 UI"）
1. **事件流**（轮询版已有，0.12.0）：源 = `.jarvis/events.jsonl`（append-only），现有写入点：闸判定、黑板、会议纪要、派活；待补：阶段变化、任务状态、工具耗时；再升级 SSE 推送。
2. **受控命令端点** `/api/jarvis/command`：白名单 `{action, args}` → 内部映射到已有工具执行，返回 `{ok, result, snapshotSummary}`；拒绝非白名单动作。
3. **快照差分**：`/api/jarvis/state?since=<seq>` 返回增量（大项目轮询省流量）。
4. **流程回放**：从 events.jsonl 重建"某时刻的阶段/任务/未决"，用于 UI 时间轴。
5. **绩效换人闭环**：连续不达标 → 自动生成"离任+补位"任务单，而不是只报告分。

### P2（能力增强）
1. 集中式审计与成本：每次工具调用的耗时/token 落事件（UI 显示"这一步花了多少"）。
2. 团队三层与子队追踪（CEO 带子队的组织图数据）。
3. 能力补足闭环：缺能力 → 市场检索 → 安装/自研插件 → 登记 components.json。
4. 记忆检索（项目内全文检索 `.jarvis/`）。
5. 交付报告导出（Markdown/JSON 可分发）。

### P3（可选）
多用户/多租户视图、权限分级、远程只读观测页。

## 四、非目标（明确不做）

- 不在插件里重写 agent 循环 / 工具执行 / 会话存储（那是 DSH 底座）；
- 不把 UI 渲染逻辑塞进插件（除已有 `office/` 演示页）；UI 独立演进，靠契约对接；
- 不用提示词承担"强制执行"，也不把"是否用了某步骤"做成闸（用户定调：流程固化，不考核步骤）；
- 不做跨项目共用记忆（会污染项目边界）。
