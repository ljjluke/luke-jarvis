## 一、数据源全景（5 个，按"真实产生度"排序）

| # | 数据源 | 路径/端点 | 内容 | 实时性 | 产生方式 |
|---|---|---|---|---|---|
| A | **团队活动快照** | HTTP `GET /plugins/dsh-agent-teams/state`（web 服务，1s 轮询 ACTIVITY_POLL_MS=1000） | 所有 workspace 的团队；每队成员 activity/currentTask/progress/unread、任务 7 字段 | **1s 级** | agent_teams 服务端组装（磁盘真相 + live subagent activity） |
| B | **团队持久状态** | `<workspace>/.agent-teams/<teamId>/team.json` | 任务**完整字段**（含 description 全文、output 完成报告、attempt 次数）；成员列表（id/name/role/model/provider/status） | 事件写入 | agent_teams 每次工具动作写盘 |
| C | **员工消息流** | `<workspace>/.agent-teams/<teamId>/inbox/<角色名>.jsonl`（captain.jsonl/ceo.jsonl/…每成员一文件） | 员工间往来消息（from/to/content/ts/deliveredAt/readAt）——**工作流真相** | 事件写入 | agent_teams 收发消息 |
| D | **公司语义层** | `<workspace>/.jarvis/company-state.json` | employees(persona/status/perfScore/strikes)/meetings/recruiting/ceo/headhunter/tasks | 事件写入 | jarvis_company / syncCompanyState（**⚠️ 见坑 2：真实项目常为空**） |
| E | **能力档案** | `<workspace>/.jarvis/cards/<角色名>.md` | 六段式角色卡（身份/思维/方法论/代表作品/红线/语言/指纹/协同） | 静态 | jarvis_distill 现场蒸馏 |

## 二、点击交互面板设计（字段级）

### 2.1 点击员工 → 「员工档案卡」3 区

**身份区**（数据 A member + B member + E 卡）：
```
头像/名字：name（如"前端实现B"）
角色：role 全文（agent_teams 存的是蒸馏时注入的完整 persona 文本，可作卡摘要）
模型：provider/model（member 字段——可显示"他是什么模型在跑"）
状态灯：activity working(绿)/idle(灰)/unknown(黄)
当前任务：currentTask id → B 里查 subject
```

**进度区**（数据 A + B + D）：
```
任务进度环：progress = owned 任务 completed占比（A 已算好）+ done/total
任务列表：他拥有的任务（B tasks filter assignee===name），每条显示
          状态(claimed/in_progress/completed/failed/cancelled) + 依赖 + depth
绩效（若有 D）：perfScore / strikes / 状态(working/on_probation/terminated)
```

**工作流区（点"屏幕"）**（数据 B output + C inbox）——你要的"详细现状"：
```
┌─ 任务详情面板 ─────────────────────────┐
│ 任务书：description 全文（CEO 派活时的  │
│   完整要求：验收标准/接口清单/约束）     │
│ 完成报告：output（员工交活结论+证据+    │
│   问题清单，数百~数千字真实文本）        │
│ 尝试次数：attempt（int，第几次成功）    │
└──────────────────────────────────────┘
┌─ 汇报轨迹面板（时间轴滚动）──────────┐
│ from 测试验证 → to CEO：v15 验收报告…  │
│ from captain → to CEO：采纳 B-01…      │
│ （inbox/<name>.jsonl 倒序，点开全文）   │
└──────────────────────────────────────┘
```

## 四、实施坑清单（全部实测确认）

**坑 1：state 端点不返回任务 output/description**
`/plugins/dsh-agent-teams/state` 的任务只有 7 字段（id/subject/status/state/assignee/dependencies/depth）。
→ output/description/attempt 必须**直接读磁盘 B**（team.json），或推动 agent_teams 端点加投影字段。

**坑 2：company-state.json 真实项目常为空（D 是"理论层"）**
实测 scan、first 两个真实项目都**没有** company-state.json——团队直接跑 agent_teams，没人调 jarvis_company 同步。
→ 3D **不能依赖 D** 做骨架；D 是可选增强（有则显示绩效/会议/招募语义）。同时意味着：要让 3D 显示绩效/会议/CEO 巡视，**得让 jarvis 流程真用 jarvis_company/syncCompanyState**（协议已约定员工动作时同步，但真实团队没执行）。

**坑 3：member.name → 卡文件非 100% 同名**
scan 项目 name="前端实现B" ↔ cards/前端实现B.md ✅；但 dsh-neon-theme 的 name 是角色泛名（产品经理/架构师/研发工程师），卡文件可能叫"产品经理-xxx.md"或"CEO-组织与变革.md"。
→ 匹配策略：① 先精确 name；② 再 name 前缀（如"产品经理"匹配"产品经理-*"）；③ 无卡则降级显示 agent_teams 的 role 全文（它内含 persona 文本）。

**坑 4：activity 只有 3 态（working/idle/unknown），不是"在思考/在写代码"**
memberActivity 只拿 `ctx.agents.get(id).status`（子代理生命周期 running/idle/ready）。
→ unknown 显示 thinking 动画是**占位**，不是真知道在想什么。**别承诺"看它思考过程"**。

**坑 5：消息是 jsonl 不是 json；按成员分文件**
inbox/<角色>.jsonl 每行一条消息。读尾部=最新。readAt 可做"已读/未读"。

**坑 6：teamId 会变、团队会归档**
state 端点返回所有 workspace 的**活跃**团队；删除的团队进 `.agent-teams/archive/`（?archived=1 可查）。
→ 3D 场景切换/历史回看需处理 archive。

**坑 7：轮询要带 token/cookie（web 服务 fence）**
state 端点是 web 服务路由，访问需会话凭证（实测带 token 才 200）。3D 前端在 DSH web 内嵌则同源自动带，独立部署要处理鉴权。

**坑 8：多人同 workspace 多团队**
state 返回 8 个团队（不同 workspace/同 workspace 多代）。3D 要么按 workspace 分楼层，要么按 captainSessionId 过滤"当前会话的团队"。

## 五、诚实边界（不许越过）

1. **没有屏幕级实时**（看不到员工正在敲什么/看什么/调什么工具）——平台无此粒度数据，只有 running/idle + 磁盘产出。
2. **attempt 是计数，无过程日志**——看不到试错过程，只有最终 output。
3. **employees.status（working/reporting/meeting）是员工动作时自己声明的近似值**，非平台实时；agent_teams activity 才是真生命周期——两者语义不同，渲染时区分（灯色用 D，活动气泡用 A）。
4. 一切"实时"以 A 端点 1s 轮询为准；B/C/D 是事件写入的磁盘真相（比 A 全但延迟取决于动作频率）。

## 六、建议实施顺序

1. **P0 骨架**：读 A 端点 → 渲染团队/工位/任务 DAG/活动气泡（1s 轮询）——纯前端，零平台改动，立即可做（端点已活，实测 8 团队）。
2. **P1 详情**：点工位 → 读 B team.json output/description + C inbox → 档案卡（能力/进度/汇报轨迹）。
3. **P2 语义**：让 jarvis 流程真用 jarvis_company 同步（D 有数据后）→ 会议室/招募/CEO 巡视/绩效上盘。
4. **P3 能力**：E 卡匹配 → 点员工弹完整六段式卡。
